# Exploring the Grammar and AST

In this exercise, you will explore grammars and parse trees through SmiLang.
SmiLang is a small programming language that supports small integers mainly.
SmiLang has a defined GLR grammar, and a parser that was autogenerated from its grammar.
The grammar is available in:

```smalltalk
SmiParser class >> #definitionComment
```

Read this grammar before starting the exercises.

The parser is available through:

```smalltalk
SmiParser parse: 'aSmiProgram'
```

It parses a program and returns its AST.

Your goal is to understand the relationship between:

```text
source program → grammar → AST
```

You will not implement the parser. Instead, you will use the grammar and the generated parser to investigate the language and the AST representation.

## 1. Explore the grammar first

Start by reading the grammar in `SmiParser class >> #definitionComment`.

Identify:

* the root rule of the grammar;
* the rule that describes a complete program;
* the rules used to describe functions;
* the rules used to describe parameters and blocks;
* the different kinds of statements;
* the different kinds of expressions;
* the rules used for lists;
* the binary operators and their precedence.

In particular, follow the grammar starting from:

```text
Program
```

until you reach expressions.

Draw this dependency as a small grammar map. For example:

```text
Program
  ↓
FunctionList
  ↓
Function
  ↓
ParameterList + Block
           ↓
      StatementList
           ↓
       Statement
           ↓
       Expression
```

Do not assume that every grammar rule corresponds to an AST node. The grammar contains rules that organize syntax, while the semantic actions determine which AST nodes are actually created. This is what happens for example with messages in the Pharo grammar we saw in the previous exercise.

### What can appear at the top level?

Look carefully at the `Program` and `FunctionList` rules.

Determine which of the following are valid complete programs:

```text
function foo() {
}
```

```text
function foo() {
    return 1;
}
```

```text
1;
```

```text
a := 1;
```

```text
foo();
```

Explain your answer by following the grammar rules rather than by trying the examples first.

In particular, identify the grammar rule that determines what may occur at the top level of a program.

Then use the parser to verify your predictions.

## 2. Functions

Now explore the structure that you discovered in the grammar.

Write programs containing:

* one function without parameters;
* one function with one parameter;
* one function with several parameters;
* several functions.

Parse each program and inspect the resulting AST.

Identify how the following grammar rules contribute to the AST:

```text
Program
FunctionList
Function
ParameterList
Block
StatementList
```

Pay attention to the list-valued parts of the AST.

For each example, draw the AST on paper and compare it with the source code.

## 3. Statements

Explore the different kinds of statements supported by the language.

Write functions containing:

* an expression statement;
* a `return` statement;
* an `if` statement;
* a `Print` statement;
* several statements in the same block.

For each program, determine which statement constructs produce their own AST node.

Compare, in particular, the AST of:

```text
a;
```

with:

```text
return a;
```

and:

```text
if a then {
    return b;
}
```

Relate each construct to the corresponding `Statement` production in the grammar.

## 4. Expressions

Explore the different expression forms.

Write an example of each using:

* integer literals;
* variable reads;
* variable assignments;
* binary operators;
* function calls;
* array creation;
* array reads;
* array writes;
* array `size`.

Inspect the AST for each example and identify the corresponding grammar production.

For each expression, first predict which production will match it. Then verify the prediction with the parser.

## 5. Binary operators

Use expressions containing several operators.

For example:

```text
1 + 2 * 3
```

and:

```text
1 * 2 + 3
```

Then explore expressions involving comparison operators.

For each expression:

1. draw the AST;
2. identify the root operator;
3. identify its left and right subtrees;
4. determine how the precedence declarations in the grammar affect the AST.

Also investigate associativity with expressions such as:

```text
1 + 2 + 3
```

and:

```text
1 - 2 - 3
```

Compare your predictions with the generated ASTs.

## 6. Arrays

Explore the array-related constructs:

```text
Array[10];
a[3];
a[3] := 42;
a.size;
```

Draw the resulting ASTs and identify the corresponding grammar productions.

Then combine these constructs in larger expressions.

For example, investigate expressions where:

* an array index is itself an expression;
* an array is assigned to a variable;
* an array element is assigned the result of an expression;
* `size` is used as part of a larger expression.

## 7. Function calls

Explore calls with:

```text
foo()
foo(a)
foo(a, b)
foo(1 + 2, a)
```

Determine how `ExpressionList` is represented in the AST.

Then investigate nested calls and calls whose arguments contain binary expressions.

## 8. Combining constructs

Write several small functions combining the constructs above.

For each program:

1. predict the relevant AST structure from the grammar;
2. parse the program;
3. inspect the generated AST;
4. compare the result with your prediction.

Include examples combining:

* assignments and binary expressions;
* function calls and binary expressions;
* arrays and assignments;
* `if` statements and blocks;
* nested expressions;
* several functions in the same program.

## 9. Grammar ↔ AST

Finally, choose several (two or three) ASTs produced by your programs.

For each AST:

1. identify the source construct represented by each node;
2. identify the grammar rule that produced that construct;
3. identify grammar rules that do not correspond directly to an AST node;
4. identify how functions, parameters, statements, and arguments are represented as lists;
5. identify how operator precedence in the grammar is reflected in the tree structure.

You should finish the exercise able to move in both directions:

```text
source code → grammar → AST
AST → grammar construct → source code
```

In particular, you should be able to determine **which programs are syntactically valid by reading the grammar**, rather than discovering the language only by trial and error.
